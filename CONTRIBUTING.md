# Contributing

Keep changes focused on emulator behavior. Include the software train, expected
behavior, and validation method in a pull request. Distinguish actual guest
results from host-only tests and simulated service responses.

Run `make check` before submitting. Do not commit firmware, dumps, fonts,
converted Java archives, SDK headers, screenshots containing proprietary assets,
credentials, or raw logs. Describe failures with a short sanitized excerpt.
Do not add vehicle flashing or activation procedures to the emulator workflow.

Contributions are accepted under GPL-2.0-or-later. Preserve third-party notices.
